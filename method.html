01

Evidence key

A pattern label, a lexical cue, a source-located mechanism, and a reviewed contract are not interchangeable.

E0 / PROPOSED

Pattern specification

The context, trigger, structure, effect, contract, variation, test obligation, and negative control define a candidate mechanism. A specification does not assert repository conformance.

E1 / RETRIEVAL

Exploratory retrieval cue

A frozen regular expression or structural matcher finds a place to inspect. A hit is not a confirmed implementation. Coverage counts any available evidence layer and is not a prevalence estimate.

E2 / SOURCE

Source-located exemplar

A repository, immutable commit, and implementation locator identify a concrete example. The atlas holds at most one canonical exemplar per candidate, so it cannot measure cross-repository contract depth.

E3 / CONTRACT

Executable or contract support

Ordering, errors, or boundaries need additional executable or contract evidence. The field guide does not infer E3 from the presence of a source anchor.

Human / AI review boundary

The study used owner-authorized AI-assisted annotation. Its 200 role-conditioned profiles cover only 16 exact structural candidates and measure one model’s consistency, not independent human agreement. Six pointcuts received majority support, eight were rejected, and two remained unresolved in that bounded sensitivity analysis. Independent human validation remains open.

03

Improvement loop

Revise from evidence outward; retain a change only when the claim–evidence link and quality gates hold.

  1. Register claims. Type each statement as descriptive, exploratory, presentational, or causal.
  2. Attach evidence. Name the frozen artifact and independent unit.
  3. Audit integration. Require both evidence and a visible manuscript link.
  4. Rank gaps. Prioritize inference-changing analysis over decorative summaries.
  5. Compute the smallest sufficient result. Preserve denominators, missing-data semantics, and uncertainty.
  6. Run statistical and manuscript QA. Retain or roll back without weakening claim boundaries.
04

Overlay boundary

The layered matcher adds Python AST symbols, multi-language declarations, artifact context, exact-symbol refinement, and source triage to frozen lexical retrieval. It remains a discovery instrument, not an automatic conformance classifier.

The first broad pass produced 851 overinclusive candidates and was rejected. Exact refinement produced 16 review candidates; eight promoted cells live in a separate, non-frozen overlay. The frozen 1,272-cell evidence matrix remains unchanged. Overlay coverage therefore cannot be read as a new field-wide prevalence estimate.

Historical cue gaps are detector gaps, not evidence of retirement. A source path change is a cue-path event, not automatically an architectural redesign.

Reproduce the study

Run these commands in a complete companion study checkout with its locked environment. Network access and GitHub authentication are needed only for discovery, freezing, and repository materialization. This static site does not include those repository caches.

source .venv/bin/activate
python -m pip install -e .

# Core frozen pipeline
make final verify

# Empirical and longitudinal extension
make longitudinal

# Corpus-level detector, matrix, statistics, and figures
make cartesian

# Layered discovery and separately reviewed overlay
make layered-overlay
make coverage-funnel

Source repository

The supplied study checkout has no configured public remote. This field guide therefore does not invent an external study-repository URL. Canonical source anchors link directly to the named public implementation repository at the recorded commit. The complete local paper is available as the companion PDF.

06

Limitations

  • The 52 records are a scoped candidate inventory, not 52 disjoint or universally established mechanisms.
  • Current cue coverage is descriptive retrieval in a selected frozen panel, not a prevalence denominator or confirmed prevalence.
  • Locating a source-backed exemplar for 51 of 52 records does not establish frequency, generality, or contract conformance elsewhere. E08 remains specification-only.
  • Lexical detectors have false-positive and construction-leakage risks. Exact structural matching and one-model profile coding do not replace independent adjudication.
  • A² is a proposed analytical lens, not a validated lifecycle model. Recording a contract does not enforce it.
  • H1 and H2 are prospective, design-only studies. No causal performance, safety, cost, or reliability benefit follows from repository association.
  • The complete paper PDF is an unpublished, untagged preview, not an accessibility-compliant publication file.

Colophon: why this field guide exists

By Haoyi Xiong

It continues an unpublished master’s research project on design patterns.

That project asked what this one still asks: when does a recurring solution become a pattern, and what must a record say before anyone else can use it? The vocabulary here is learned from the Gang of Four’s catalog, Roy T. Fielding’s account of architectural styles in network software, and Douglas C. Schmidt’s writing on distributed-computing patterns and the Pattern-Oriented Software Architecture series.

Those teachers insisted on the discipline this guide tries to keep: name the join point, state the contract, separate what may vary, and show the evidence. The field guide is dedicated to the research that remained unpublished—and to the readers who can carry the question further.

  • Roy T. Fielding, Architectural Styles and the Design of Network-based Software Architectures (2000)
  • Douglas C. Schmidt — distributed-computing patterns and the POSA series
  • Erich Gamma, Richard Helm, Ralph Johnson, and John Vlissides, Design Patterns: Elements of Reusable Object-Oriented Software (1994)
POHE / Pattern-Oriented Harness Engineering

How to read the evidenceColophon

Analytical diagrams, prompt sketches, and code designs describe proposed contracts. They are not observed traces, repository class declarations, or evidence that any implementation conforms.
