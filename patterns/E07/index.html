04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Candidate runtime and evaluation suite are isolated and available.
Ensures
Every selected candidate has execution and fitness provenance.
Invariant
Evaluation budget and security boundaries hold across all candidates.
Violation
Crash, timeout, unsafe code, or invalid fitness removes or quarantines candidate.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Generate executable candidates in an isolated runtime, evaluate every selected candidate, and retain execution and fitness provenance for the archive.
CODE DESIGN / PYTHON
def search(task, evaluator, archive):
    candidate = generator.propose(task, archive)
    with sandbox.run(candidate) as run:
        result = run.output()
    fitness = evaluator.score(result, task)
    archive.add(CandidateRecord(candidate, result, fitness))
    return archive.best()

Illustrative design sketch. Selection is only as trustworthy as the isolation and provenance of the run. This example is a teaching aid, not implementation evidence or a conformance claim.
