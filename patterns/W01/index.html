03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
A task is decomposed into ordered agent or prompt stages.
Trigger
One stage produces an intermediate result consumed by the next.
Structure
Stage graph, typed handoff payload, validation, and terminal output.
Effect
Stages execute in order and downstream input is attributable to upstream output.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Stage order and handoff schema are defined.
Ensures
Every stage receives validated input and the final output identifies its stage lineage.
Invariant
A later stage cannot execute before its prerequisites complete.
Violation
A stage failure stops, retries, or branches according to declared policy.

Negative control

Independent prompts with no intermediate-result dependency do not count.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Run the named stages in order. Validate each handoff against its declared schema, and make the final output identify the stage lineage that produced it.
CODE DESIGN / PYTHON
def run_chain(stages, initial_input):
    payload, lineage = initial_input, []
    for stage in stages:
        validated = stage.input_schema.validate(payload)
        payload = stage.run(validated)
        lineage.append(stage.id)
    return ChainResult(output=payload, lineage=lineage)

Illustrative design sketch. A chain without validated handoffs is a sequence of unrelated prompts. This example is a teaching aid, not implementation evidence or a conformance claim.
