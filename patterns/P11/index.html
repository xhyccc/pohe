03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
The harness exposes both primitive effects and multi-step procedures.
Trigger
The agent chooses a tool or workflow entry point.
Structure
Separate effect/result contracts and workflow ownership of sequencing.
Effect
Workflow orchestration is not mistaken for a single external side effect.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Tool and workflow descriptors have distinct schemas and execution paths.
Ensures
Retry, budget, and result accounting bind to the correct unit.
Invariant
A workflow cannot hide duplicate irreversible tool effects.
Violation
Nested failures and retries produce explicit ownership and cost records.

Negative control

A single function that happens to call another function is not enough.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Distinguish a primitive tool call from a multi-step workflow. Give each a separate descriptor and execution path, and bind retry, budget, and result accounting to the correct unit.
CODE DESIGN / PYTHON
@dataclass(frozen=True)
class ToolCall:
    name: str
    arguments: dict

@dataclass(frozen=True)
class WorkflowRun:
    name: str
    steps: list[ToolCall]

def execute(unit, runtime):
    if isinstance(unit, WorkflowRun):
        return runtime.run_workflow(unit)
    return runtime.invoke_tool(unit)

Illustrative design sketch. One boundary with two units; shared accounting must not blur which unit failed. This example is a teaching aid, not implementation evidence or a conformance claim.
