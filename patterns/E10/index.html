03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
Harness traces and evaluation results are available for improvement.
Trigger
Analysis identifies a failure or opportunity and proposes a harness change.
Structure
Trace schema, analyzer, authorized edit scope, evaluation gate, and regression suite.
Effect
The harness change is trace-linked and accepted only after evaluation.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Trace links compare runs and identify the affected harness component.
Ensures
Accepted changes retain observation, hypothesis, diff, and evaluation provenance.
Invariant
A changed harness still passes regression and security checks.
Violation
Non-reproducible traces or regressions reject or quarantine the change.

Negative control

Logging without a trace-to-change decision is not E10.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Compare traces to identify an affected harness component, propose a change, and evaluate it before acceptance. Retain the observation, hypothesis, diff, and evaluation as one provenance chain.
CODE DESIGN / PYTHON
def evolve(trace_pair, harness):
    diagnosis = diagnose(trace_pair)
    if diagnosis.component is None:
        return NoChange(diagnosis)
    diff = propose_edit(harness, diagnosis)
    result = evaluate(harness.apply(diff))
    return EvolutionRecord(
        observation=trace_pair.evidence,
        hypothesis=diagnosis,
        diff=diff,
        evaluation=result,
    )

Illustrative design sketch. Observability becomes evolution only when the trace is tied to an evaluated change. This example is a teaching aid, not implementation evidence or a conformance claim.
