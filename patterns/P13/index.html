03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
New work is represented by durable append-only records.
Trigger
A consumer polls or subscribes to unseen records.
Structure
Event identity, append order, consumer cursor, and acknowledgement.
Effect
Work advances from the log without replaying already completed effects.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Records have stable identity and consumers retain progress.
Ensures
Each effectful unit has an idempotency or acknowledgement rule.
Invariant
Consumer crash does not erase unacknowledged work.
Violation
Duplicate delivery is deduplicated or documented as at-least-once.

Negative control

An in-memory queue is not log-as-queue.

Variation & lifecycle

Permitted variation

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Consume durable work records with stable identity. Claim a record before acting, acknowledge only after the effect is committed, and make retries idempotent.
CODE DESIGN / PYTHON
def consume_one(queue, handler):
    record = queue.claim(timeout=30)
    if record is None:
        return None
    if not queue.is_seen(record.id):
        handler.apply_once(record.id, record.payload)
        queue.mark_seen(record.id)
    queue.ack(record.id)
    return record.id

Illustrative design sketch. The acknowledgement rule, not the transport name, makes the queue durable. This example is a teaching aid, not implementation evidence or a conformance claim.
