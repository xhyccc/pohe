03

Pointcut

Where the mechanism applies. All four dimensions belong to the proposed match, not just its vocabulary.

Context
A subject changes state or emits lifecycle information.
Trigger
The subject publishes a change notification.
Structure
Subscription registry, event payload, and observer callbacks.
Effect
Currently registered observers are notified under declared ordering semantics.
04

Protected contract

The obligation that clients, operators, and auditors should be able to rely on.

Requires
Observer identity and subscription lifetime are defined.
Ensures
Notification follows the event and unsubscribed observers no longer receive it.
Invariant
Observer failure does not corrupt subject state.
Violation
Callback errors and cascades are isolated or propagated by explicit policy.

Negative control

Polling the subject rather than notification is not the observer pointcut.

06

Prompt + code design

An illustrative prompt and a small design sketch for the proposed contract. Names and APIs are invented; this is not a repository excerpt.

PROMPT SKETCH
Notify subscribers after a subject change, within their declared subscription lifetime. An unsubscribed observer must not receive later notifications.
CODE DESIGN / PYTHON
class Subject:
    def __init__(self):
        self.observers = {}

    def subscribe(self, observer):
        self.observers[observer.id] = observer

    def unsubscribe(self, observer_id):
        self.observers.pop(observer_id, None)

    def publish(self, event):
        for observer in list(self.observers.values()):
            observer.notify(event)

Illustrative design sketch. Subscription lifetime is the contract; notification order is secondary. This example is a teaching aid, not implementation evidence or a conformance claim.
